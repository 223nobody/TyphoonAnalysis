# 图像分析功能重构总结

**日期**: 2026-04-24  
**项目**: TyphoonAnalysis  
**当前结论**: 图像分析模块已经从早期“功能不断叠加”的设计思路，收束为“少量核心模式 + 分层后端实现”的简化方案。前端只保留用户最常用的三种分析模式，后端则保留基础统计与高级特征接口用于兼容、调试和后续扩展。

---

## 一、重构后的总体定位

本次调整并不是简单删除功能，而是将图像分析模块整理为更清晰的三层结构：

1. **文件上传与结果持久化层**：负责图像保存、去重、元数据记录、分析记录状态管理。
2. **结构化分析层**：负责使用 OpenCV 与可选的深度学习接口输出中心、强度、台风眼和结构评分等可计算指标。
3. **多模态语义解释层**：在 `hybrid_ai` 模式下调用 Qwen-VL，对结构化结果进行 few-shot 增强解释，并生成 Markdown 报告。

这意味着当前图像分析模块的核心目标已经从“追求尽可能多的分析入口”，转为“保证主流程稳定、结果可追踪、论文表述与代码一致”。

## 二、当前代码中的实际实现

### 2.1 主要文件与职责

| 文件 | 作用 |
| ---- | ---- |
| `backend/app/api/v1/images.py` | 暴露图像上传、分析、查询、删除接口，组织响应结构 |
| `backend/app/services/image/image_service.py` | 图像分析总调度器，负责保存文件、创建分析记录、分发模式、回写数据库 |
| `backend/app/services/image/opencv_analyzer.py` | 传统视觉分析，输出中心、强度、台风眼、螺旋结构 |
| `backend/app/services/image/dl_analyzer.py` | 预留的 ResNet50 深度学习接口，当前为可选能力 |
| `backend/app/services/image/fusion_analyzer.py` | 融合 OpenCV 与深度学习结果，生成结构化综合输出 |
| `backend/app/services/ai/qwen_image_service.py` | few-shot 视觉大模型调用，生成摘要、报告与风险提示 |
| `backend/app/models/image.py` | `typhoon_images` 图像元数据表 |
| `backend/app/models/image_analysis.py` | `image_analysis_results` 分析结果表 |
| `frontend/src/components/ImageAnalysis.jsx` | 图像上传、模式选择、报告展示与导出页面 |

### 2.2 前端简化后的用户可见模式

虽然后端仍保留 `basic` 和 `advanced` 两个兼容模式，但当前前端页面只向用户开放以下三种主模式：

| 模式 | 页面是否开放 | 功能定位 |
| ---- | ---- | ---- |
| `hybrid_ai` | 是 | 结构化分析 + Qwen-VL few-shot 报告生成 |
| `fusion` | 是 | 仅输出结构化融合结果 |
| `opencv` | 是 | 仅使用传统视觉方法进行快速分析 |
| `basic` | 否 | 用于基础统计调试与向后兼容 |
| `advanced` | 否 | 用于图像质量与视觉特征调试 |

前端默认分析模式为 `hybrid_ai`，默认图像类型为 `visible`，同时保留 `infrared` 选项。

## 三、后端分析流程

### 3.1 上传与存储

图像上传由 `POST /api/v1/images/upload` 处理。服务端首先校验 MIME 类型是否属于图像，再调用 `ImageAnalysisService.save_image()` 完成以下工作：

1. 清洗文件名并检查是否为空；
2. 依据 `filename` 查询数据库，拦截同名重复上传；
3. 使用 Pillow 读取图像宽高和格式；
4. 将文件落盘到 `backend/data/images/<image_type>/`；
5. 在 `typhoon_images` 表中写入文件路径、图像类别、台风编号、宽高、格式、文件大小和上传时间。

这种实现方式保证了图像原文件和分析结果之间存在稳定映射，后续查询、删除和论文截图取证也更方便。

### 3.2 分析状态机

图像分析由 `ImageAnalysisService.analyze_image()` 统一驱动，执行顺序如下：

```text
接收 image_id
  -> 创建 image_analysis_results 记录（status=processing）
  -> 根据 analysis_type 分发到具体分析器
  -> 补充 image_metadata 与 visual_metrics
  -> 写回结构化结果、摘要、报告、风险标记、耗时
  -> 完成时置为 completed，异常时置为 failed
```

数据库中 `image_analysis_results` 采用“结构化结果与文本报告分开存储”的策略：

- `result_data` 保存结构化主结果；
- `summary` 保存摘要；
- `ai_report` 保存 Markdown 报告；
- `risk_flags` 保存风险提示；
- `fewshot_examples` 保存 few-shot 样例记录；
- `ai_model`、`processing_time`、`error_message` 用于追踪调用情况。

这种拆分有利于前端分别渲染结构化指标卡片和长文本报告，也方便论文中说明“结果可回溯、任务状态可跟踪”。

## 四、结构化分析层实现

### 4.1 OpenCV 分析器

`OpenCVAnalyzer` 是当前图像模块最稳定的基础能力，主要输出台风中心、强度等级、台风眼和螺旋结构。

#### 1. 中心检测

系统先对图像灰度化并进行高斯模糊，然后根据图像类型执行阈值分割、形态学开闭运算和轮廓提取。对于候选轮廓，采用圆形度筛选最接近台风眼形态的区域：

$$
C=\frac{4\pi A}{P^2}
$$

其中，\(A\) 表示轮廓面积，\(P\) 表示轮廓周长，\(C\) 越接近 1 表示轮廓越接近圆形。最终再结合图像矩计算候选区域中心坐标。

#### 2. 强度估计

强度估计采用亮度、纹理和对流强度的线性加权：

$$
S_{img}=0.4\frac{255-\bar{I}}{255}+0.3S_{tex}+0.3S_{conv}
$$

其中，\(\bar{I}\) 为平均亮度，\(S_{tex}\) 为 Sobel 梯度生成的纹理得分，\(S_{conv}\) 为 Laplacian 统计得到的对流活动得分。计算结果再映射为热带低压、热带风暴、强热带风暴、台风、强台风和超强台风六级结果。

#### 3. 台风眼与螺旋结构

台风眼检测以中心附近局部区域为对象，比对中心窗口与周边窗口的平均灰度差异；当中心区域明显暗于周边区域时，判断可能存在台风眼，并按固定像素比例估算眼区直径。螺旋结构分析则在不同半径环带上统计像素波动，将其平均值作为 `spiral_score`。

### 4.2 附加视觉指标

在完成主分析后，`image_service.py` 还会统一附加一组视觉上下文指标，写入 `details.visual_metrics`：

- `brightness`
- `contrast`
- `sharpness`
- `texture`
- `cloud_coverage`
- `min_intensity`
- `max_intensity`
- `dynamic_range`

其中，云量估计和动态范围可表示为：

$$
\eta_{cloud}=\frac{N(I>128)}{N}, \qquad
R=I_{max}-I_{min}
$$

这些指标并不直接决定最终台风等级，但它们为调试、可解释性分析和 AI 报告补充提供了量化背景。

## 五、融合层实现

`fusion` 模式由 `ImageAnalysisService._fusion_analysis()` 触发，其目标是在不强依赖深度学习模型的前提下，尽量形成统一的结构化输出。

### 5.1 中心融合

若 OpenCV 与深度学习模型均返回中心坐标，系统计算二者欧氏距离：

$$
d=\|c_{cv}-c_{dl}\|_2
$$

当 \(d<50\) 像素时，采用加权平均方式融合中心位置：

$$
c_f=0.3c_{cv}+0.7c_{dl}
$$

若差异过大，则直接选择置信度更高的一方。若深度学习模型未加载成功，系统自动退化为 OpenCV 结果。

### 5.2 强度融合与综合置信度

强度融合遵循以下规则：

1. 两种方法结果一致，则直接输出；
2. 相差 1 个等级时，选择置信度更高的结果；
3. 相差超过 1 个等级时，将结果标记为“不确定”。

最终综合置信度为中心检测与强度估计的加权和：

$$
P_{all}=0.6P_{center}+0.4P_{intensity}
$$

### 5.3 当前实现边界

需要特别强调的是，`DLAnalyzer` 当前仍是“可选增强能力”，并不是论文中可以写成“已稳定部署并广泛使用”的成熟模块。它会尝试读取：

- `data/models/typhoon_center_resnet50.pth`
- `data/models/typhoon_intensity_resnet50.pth`

若模型文件不存在或加载失败，融合流程不会中断，而是继续返回 OpenCV 结果，并在后续 `hybrid_ai` 模式中追加风险提示。这正是当前代码层面的真实能力边界。

## 六、多模态语义解释层实现

### 6.1 `hybrid_ai` 模式的基本逻辑

`hybrid_ai` 并不是“直接把图片发给大模型让它自由发挥”，而是先做结构化分析，再做大模型解释：

```text
图像
  -> fusion 结构化分析
  -> 读取 few-shot 样例
  -> 拼接结构化结果快照 + 样例说明 + 目标图像
  -> 调用 Qwen-VL
  -> 返回 summary / markdown_report / risk_flags / consistency_score
```

在具体实现中，`QwenImageService` 会从 `backend/data/images/test/examples.json` 中读取最多 3 个与图像类型匹配的样例，并把样例图与目标图一并发送给视觉模型。

### 6.2 AI 输出字段

大模型响应被规范化为以下核心字段：

- `summary`
- `overall_assessment`
- `eye_detected`
- `eye_position_description`
- `eye_confidence`
- `eye_evidence`
- `center_location_hint`
- `intensity_assessment`
- `organization_assessment`
- `development_stage`
- `cloud_system_description`
- `analysis_highlights`
- `analysis_limitations`
- `consistency_score`
- `risk_flags`
- `markdown_report`

因此，当前 AI 在本模块中的职责主要是“解释结构化结果、补充语义描述、输出面向用户的报告”，而不是替代底层图像特征计算。

### 6.3 一致性与风险控制

`hybrid_ai` 模式具有明显的结果校验机制。若 AI 返回了一致性评分，则采用该评分；否则回退到结构化分析的综合置信度：

$$
S_{cons}=
\begin{cases}
S_{ai}, & \text{视觉模型返回一致性评分时} \\
P_{all}, & \text{否则}
\end{cases}
$$

系统还会在以下情况下自动追加 `risk_flags`：

1. AI 对台风眼是否存在的判断与结构化结果冲突；
2. 一致性评分低于 0.65；
3. 未能成功加载 few-shot 样例；
4. 深度学习模型未加载，结构化结果主要依赖 OpenCV；
5. Qwen-VL 调用失败，系统只能回退到结构化结果。

这种设计说明当前系统已经把大模型纳入“带校验的辅助解释层”，而不是把最终结论完全交给外部模型。

## 七、与旧版方案相比的简化点

结合当前代码，图像分析模块的简化主要体现在以下几个方面：

### 7.1 前端交互简化

用户页面不再暴露 `basic` 和 `advanced`，而是只保留：

- `hybrid_ai`
- `fusion`
- `opencv`

这样可以避免普通用户面对过多技术选项，同时保留后端兼容能力用于调试和论文实验描述。

### 7.2 分析目标简化

当前主流程不再强调“图像端必须完成高精度深度学习推理”，而是改为：

- 结构化部分优先保证可运行、可解释；
- AI 部分优先生成摘要、报告和风险提示；
- 深度学习部分作为增强能力接入，而非强依赖前提。

### 7.3 调度方式简化

当前实现为同步接口调用，不包含消息队列、异步任务调度、进度推送或缓存复用机制。论文描述时应据实写成“同步处理 + 状态可查询”，不要写成“异步流水线分析平台”。

## 八、建议同步到论文中的关键表述

为保证论文与代码一致，图像分析章节应重点体现以下几点：

1. 前端已经简化为三种主模式，`basic` 与 `advanced` 主要用于兼容与调试。
2. 图像分析是“结构化分析先行、视觉大模型补充解释”的分层方案。
3. `fusion` 模式存在深度学习接口，但当前代码允许无模型文件时自动降级。
4. `hybrid_ai` 模式的核心创新点在于 few-shot 样例增强、结构化结果注入和风险提示机制，而不是纯粹的端到端黑盒识别。
5. 数据库存储采用“结构化结果、文本报告、风险标记分字段持久化”的方式，可支持结果回显与审计追踪。

## 九、结论

当前图像分析模块已经完成从“概念性多方案堆叠”到“可落地、可解释、可在论文中准确描述”的重构。其真实形态可以概括为：

- **用户界面上**：三种主模式，流程清晰；
- **结构化分析上**：以 OpenCV 为稳定基础，以融合器统一输出；
- **AI 增强上**：以 few-shot 视觉模型生成辅助解释和 Markdown 报告；
- **工程实现上**：支持持久化、风险提示、失败回退和结果追踪。

因此，论文中的图像分析部分应围绕“简化后的分层实现”展开，而不宜继续沿用旧版本中关于“深度学习主导、阶段化训练计划、预期准确率”的表述。
